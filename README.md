# DiskDownloader

Приложение для копирования папок Яндекс Диска со всей структурой подпапок. Скачивает доступные оригиналы, докачивает прерванные загрузки и при следующих проходах находит появившиеся или восстановленные файлы.

Основной способ работы — оконный интерфейс для macOS и Windows. На Яндекс Диске ничего не меняется; локальные копии удалённых с Диска файлов сохраняются.

## Возможности

- Несколько исходных папок в одной очереди, отдельное назначение для каждой, включая внешние диски.
- Пропуск готовых неизменившихся файлов и докачка частичных загрузок через HTTP Range.
- Проверка скачанного оригинала и атомарная замена прежней копии при изменении.
- Повторение всей очереди по кругу с паузой и повторными попытками недоступных файлов.
- Сохранение доступного превью на месте недоступного оригинала с последующим восстановлением оригинала.
- Отдельные счётчики оригиналов и превью, журнал и отчёт последнего прохода.
- Хранение OAuth-токена в Связке ключей macOS или Диспетчере учётных данных Windows.
- Подготовка Python при первом запуске, если подходящая среда не найдена.

## Быстрый запуск

Скачайте готовую сборку из [Releases](https://github.com/chylkov/DiskDownloader/releases), распакуйте её целиком и откройте файл запуска двойным щелчком:

| Система | Пользовательский архив | Файл запуска |
| --- | --- | --- |
| macOS | [DiskDownloader-macOS.zip](https://github.com/chylkov/DiskDownloader/releases/latest/download/DiskDownloader-macOS.zip) | `run-gui.command` |
| Windows | [DiskDownloader-Windows.zip](https://github.com/chylkov/DiskDownloader/releases/latest/download/DiskDownloader-Windows.zip) | `run-gui.bat` |

Из исходного проекта открывается тот же файл запуска. Исходники можно получить кнопкой **Code → Download ZIP** на GitHub или через Git:

```sh
git clone https://github.com/chylkov/DiskDownloader.git
cd DiskDownloader
```

В каждом архиве **15 файлов**: интерфейс, модули, две иконки, помощники своей системы и краткое руководство [docs/GUI.md](docs/GUI.md) под именем `README.md`. CLI, тесты и инструменты остаются в исходном проекте. См. [сборку архивов](#сборка-пользовательских-архивов).

Нужен **Python 3.10+ с Tkinter**. Приложение использует стандартную библиотеку, пакеты через `pip` не требуются. Встроенного Python и отдельного `.exe` в архивах нет.

Подходящий установленный Python используется сразу. Иначе лаунчер предложит установку: **Y** — согласиться, **Enter / N** — отменить. После установки и проверки программа запускается автоматически.

### Установка Python на macOS

Лаунчер ищет Python в `.venv`, `PATH`, установках python.org и Homebrew. Для формы проверяется реальное окно **Tk 8.6.13+**. Неподходящие среды пропускаются без изменения файлов.

Автоматически устанавливается официальный **Python 3.14.8 universal2**, Intel / Apple Silicon, **macOS 10.15+**. Нужны интернет и права администратора. Проверяются SHA-256, подпись Python Software Foundation и Gatekeeper; пароль запрашивается системным окном macOS.

Путь установки — `/Library/Frameworks/Python.framework/Versions/3.14`. Официальный `Install Certificates.command` от обычного пользователя загружает `certifi` из PyPI для HTTPS. Повреждённый установленный Python 3.14 автоматически не перезаписывается: потребуется ручное восстановление.

### Установка Python на Windows

Проверяются Windows-окружение `.venv`, среда приложения и доступные команды Python. `.venv` с Mac пропускается; повреждённое Windows-окружение требует восстановления.

Предлагается официальный **Python 3.14.8 с Tcl/Tk**, с проверкой SHA-256 и подписи Python Software Foundation. Он устанавливается **для текущего пользователя без прав администратора** в `%LOCALAPPDATA%\DiskDownloader\Python`; `PATH` и глобальный Python Launcher не меняются.

Зарегистрированный другой Python 3.14 автоматически не изменяется. При необходимости добавьте **Tcl/Tk and IDLE** через **Modify** или восстановите его через **Repair**.

При ручной установке используйте [Python для macOS](https://www.python.org/downloads/macos/) или [Python для Windows](https://www.python.org/downloads/windows/) с поддержкой Tcl/Tk.

## Подключение и OAuth-токен

1. Нажмите **«Получить токен»**: страница Яндекса откроется в системном браузере.
2. Войдите в аккаунт, из которого нужно копировать файлы, нажмите **«Разрешить»** и скопируйте выданный токен.
3. Вставьте его в скрытое поле через **Cmd+V** на macOS или **Ctrl+V** на Windows и нажмите **«Подключиться»**.

Страницу можно [открыть вручную](https://oauth.yandex.ru/authorize?response_type=token&client_id=98979c5296c34f9faea9ab76847efb68). Публичный Client ID задан в `OAUTH_TOKEN_URL` в [disk_downloader_gui.py](disk_downloader_gui.py); это не токен.

**Для другого аккаунта:** доступ через встроенный Client ID зависит от настроек OAuth-приложения. Если оно имеет тип «Для доступа к API», Яндекс ограничивает его данными разработчика. При отказе получите токен своего приложения с доступом **`cloud_api:disk.read`**: [типы приложений](https://www.yandex.ru/dev/id/doc/ru/register-client), [регистрация](https://yandex.com/dev/id/doc/ru/register-api).

Для своего приложения используйте `https://oauth.yandex.ru/authorize?response_type=token&client_id=ВАШ_CLIENT_ID` и вставьте токен в форму без изменения кода. Подробности — в [инструкции Яндекса](https://yandex.com/dev/id/doc/ru/tokens/debug-token). Пароль вводится только на сайте Яндекса.

### Сохранение и вставка

При подключении или запуске копирования токен сохраняется в **Связке ключей macOS** или **Диспетчере учётных данных Windows** и подставляется в следующий раз. При недоступном хранилище работа с введённым токеном продолжается; сохранение повторяется при следующем подключении.

- Токен не записывается в JSON, обычный файл или журнал. Исходный код также не должен содержать действующий токен.
- Запись привязана к папке программы: после переноса или переименования может понадобиться прежний токен.
- Переменная **`YANDEX_DISK_TOKEN`**, если задана, имеет приоритет над сохранённым токеном.
- **«Удалить»** стирает сохранённую запись и очищает поле, но не отзывает разрешение в аккаунте Яндекса.

Можно вставить токен или адрес `https://oauth.yandex.ru/verification_code#access_token=...`. Пробелы и невидимое форматирование очищаются; скрытые точки/звёздочки и посторонние буквы отклоняются. Для замены поля сначала выделите всё через **Cmd+A / Ctrl+A**.

## Работа с очередью папок

1. Укажите общую локальную папку для новых заданий, в том числе на внешнем диске.
2. Откройте ветки дерева Яндекс Диска, выделите папки и нажмите **«Добавить выбранные»**. Несколько папок выделяются с Cmd/Ctrl, диапазон — с Shift.
3. Если исходный путь известен, используйте **«Добавить по пути»**, например `/Архив/Фото`.
4. Выберите отдельное назначение для каждого источника. **«Куда сохранить»** меняет выбранную строку; общая папка применяется к новым строкам.
5. При необходимости включите проходы по кругу или сохранение превью, затем нажмите **«Начать копирование»**.

Папки обрабатываются последовательно, файлы внутри текущей папки — параллельно. **«Вкл. / выкл.»** отключает строку, **«Удалить из списка»** оставляет скачанные файлы. Очередь сохраняется автоматически.

Сохраняется **содержимое** источника: `/Архив/Фото/a.jpg` из папки `/Архив` станет `backup/Фото/a.jpg`. Доступные пустые подпапки тоже создаются.

### Параметры и счётчики

| Параметр | Значение по умолчанию | Назначение |
| --- | --- | --- |
| Потоков | `3` | Одновременные загрузки одной папки; допустимо 1–32 |
| Таймаут, с | `60` | Ожидание подключения или чтения из сети; допустимо 1–600 |
| Повторов | `3` | Дополнительные попытки после ошибки сверх первой; допустимо 0–10 |
| Проходить по кругу | Выключено | Повторять всю включённую очередь до остановки |
| Пауза между кругами, с | `60` | Пауза после завершения очереди; допустимо 1–86 400 |
| Сверять SHA-256 | Выключено | Дополнительно читать и хешировать уже сохранённые файлы |
| Сохранять превью при ошибке оригинала | Выключено | Запрашивать доступное изображение предпросмотра после ошибки оригинала |

Рядом с **«Ход копирования»** считаются новые и заменённые оригиналы за запуск, при повторении — также за текущий круг. `[ЕСТЬ]` и частичные загрузки не учитываются; превью считаются отдельно. Новый запуск кнопкой сбрасывает счётчики.

**«Остановить»** сохраняет прогресс и прерывает паузу между кругами. Активный сетевой запрос может ждать таймаута. Перед изменением параметров остановите копирование.

## Как работает копирование

Каждый запуск и каждый круг заново обходят **выбранные папки со всеми подпапками**, а не весь аккаунт, если корень Диска не выбран явно.

1. API возвращает метаданные папок постранично. Обход и загрузки идут параллельно, без ожидания единого полного списка файлов.
2. Для файла определяется версия: размер и SHA-256, либо MD5, либо время изменения, если сервер не предоставил контрольную сумму.
3. Версия сравнивается с базой прогресса, локальными размером и временем изменения. Готовый неизменившийся файл пропускается: **`[ЕСТЬ]`**.
4. Отсутствующий файл скачивается; частичный докачивается через HTTP Range. Без поддержки диапазона загрузка начинается заново. Частичная копия другой версии не используется.
5. Проверяются размер и контрольные суммы сервера. Затем файл атомарно переносится на итоговый путь и обновляется база.
6. Изменившийся оригинал заменяет прежнюю копию после полной загрузки и проверки. До этого прежняя копия сохраняется. Новые архивы старых версий не создаются.

**`[ЕСТЬ]` означает проверку без повторного скачивания.** Метаданные Диска запрашиваются каждый раз; содержимое известного неизменившегося файла обычно не перечитывается. **«Сверять SHA-256»** включает полное локальное чтение и сравнение с сохранённым хешем. Неизвестная копия или файл с изменившимися локальными признаками также может перечитываться для проверки по сумме Диска.

Ошибка файла или подпапки не останавливает остальные загрузки. Следующий круг заново обходит источники и пробует недоступные оригиналы.

## Превью вместо недоступного оригинала

Галочка **«Сохранять превью при ошибке оригинала»** включает запрос `XXXL` без обрезки после исчерпания попыток скачивания. Ошибки локального диска и авторизации API не запускают такой запрос.

- Превью сохраняется **на том же пути и под тем же именем**, что и оригинал. Его формат может отличаться от расширения: например, `.heic` может временно содержать JPEG.
- Это резервное изображение: оно помечается отдельно в базе и журнале, не считается оригиналом и не убирает ошибку из отчёта.
- Уже сохранённое превью текущей версии повторно не загружается. Прежняя полная копия оригинала и изменённый пользователем локальный файл не заменяются уменьшенным изображением.
- Каждый круг или запуск **снова пытается скачать оригинал даже при выключенной проверке SHA-256**. Проверенный оригинал атомарно заменяет превью; его отметка удаляется.
- Частичная загрузка оригинала хранится отдельно и может продолжиться независимо от превью.

Наличие превью в браузере не гарантирует его доступность через API. Поддерживаются JPEG, PNG, GIF и WebP до 32 МиБ, с проверкой длины, типа и признаков формата. Сумма оригинала к уменьшенному изображению не применяется.

## Настройки и служебные данные

`download-gui.json` рядом с программой хранит `version`, `tasks` и параметры `workers`, `retries`, `timeout`, `verify`, `repeat`, `repeat_delay`, `save_previews`. Задание содержит `disk_path`, `output`, `enabled`; токена нет. Редактировать файл вручную обычно не требуется.

При отсутствии GUI-настроек может импортироваться одна личная папка из прежнего `download.json`. Публичная ссылка не преобразуется в личный источник; настройки при чтении не переписываются.

В каждой папке назначения создаётся собственная служебная папка:

```text
backup/
├── Фото/a.jpg
└── .disk-downloader/
    ├── state.sqlite3
    ├── partials/
    │   ├── <хеш пути>.part
    │   └── <хеш пути>.json
    ├── events.log
    ├── last-run.json
    └── run.lock
```

| Файл | Содержимое |
| --- | --- |
| `state.sqlite3` | Идентичность источника, сведения об оригиналах, контрольные суммы и отдельные отметки превью |
| `partials/` | Незавершённые оригиналы и сведения об их версии; временные превью до проверки |
| `events.log` | Журнал работы и ошибок |
| `last-run.json` | Итог последнего прохода этой папки и проблемные пути |
| `run.lock` | Защита от одновременной записи в одно назначение |

**Сохраняйте `.disk-downloader` вместе с копией:** в ней отметки превью и прогресс. Архивы `versions/` от старых выпусков остаются на месте; новые не создаются.

Назначения включённых заданий не должны совпадать или быть вложенными друг в друга. Источник определяется путём на Диске и токеном: смена любого из них требует другого назначения.

## Ограничения и сохранность

- Копируется только то, что Яндекс Диск сейчас перечисляет и отдаёт через API. Успешный обход не доказывает восстановление всех когда-либо существовавших файлов.
- Удалённые серверные данные не восстанавливаются, ограничения доступа не обходятся. Недоступные файлы пробуйте снова позже.
- Символические ссылки, Windows junction и опасные пути отклоняются. Конфликты регистра / Unicode и несовместимые имена Windows сообщаются как ошибки без автоматического переименования.
- `.disk-downloader` в корне назначения зарезервировано. Одноимённый элемент верхнего уровня источника вызовет конфликт.

## Частые проблемы

| Симптом | Что проверить |
| --- | --- |
| Кнопки на Mac требуют удерживания | Проверьте Tk 8.6.13+; используйте лаунчер или обновлённый Python |
| Нет Python или Tkinter | Запустите `.command` / `.bat` и подтвердите установку либо установите Python с Tcl/Tk вручную |
| Python установлен, но HTTPS не работает на Mac | Выполните `/Applications/Python 3.14/Install Certificates.command` от своего пользователя; проверьте доступ к PyPI |
| Windows сообщает о другом Python 3.14 | Используйте Modify → Tcl/Tk and IDLE или Repair; эта установка автоматически не меняется |
| Пустой / неверный токен, HTTP 401 | Вставьте токен или адрес выдачи; точки скрытого поля токеном не являются. Проверьте отзыв и срок токена |
| Отказ авторизации другого аккаунта | Проверьте тип OAuth-приложения или получите токен своего приложения с правом чтения |
| Между строками журнала проходит около минуты | Запрос может ждать таймаута 60 с; пауза между кругами действует только после всей очереди |
| Есть `[ОШИБКА]`, но загрузки продолжаются | Частичный результат: смотрите `last-run.json`, повторите обход или включите круги |
| «Копия другого источника» | Проверьте прежний токен и исходный путь; для нового источника выберите новое назначение |
| Назначение уже обрабатывается | Завершите другой запуск; не удаляйте его блокировку во время работы |

## Обновление и перенос

Перед обновлением остановите копирование. Заменяйте файлы приложения, сохраняя `download-gui.json`, все папки назначения с `.disk-downloader` и установленную среду Python, включая рабочую `.venv`.

Оставляйте папку программы по прежнему пути для автоматической подстановки токена. После её переноса может понадобиться повторная вставка прежнего токена; в архивы и настройки он не входит.

### Продолжить копию с Mac на Windows

1. Остановите копирование и перенесите каждое локальное назначение **целиком с `.disk-downloader`**.
2. Распакуйте Windows-архив отдельно. Не переносите `download-gui.json` и `download.json` с Mac: пути `/Users/...` и `/Volumes/...` не указывают на нужные назначения Windows.
3. Заново добавьте те же папки Яндекс Диска и для каждой выберите уже перенесённое назначение, например `E:\DiskBackup\Фото`.
4. Один раз вставьте **тот же OAuth-токен**: запись Связки ключей автоматически не переносится. Другой токен требует новой папки назначения.

После переноса программа заново сверит источник и локальные файлы. Если при копировании изменились локальные времена файлов, проверка может потребовать чтения их содержимого.

## Консольный режим в исходном проекте

CLI копирует один личный или публичный источник и не входит в GUI-архивы. Запуск из исходного проекта: `run.command` на Mac, `run.bat` на Windows или команды:

```sh
python3 disk_downloader.py --disk-path '/Архив' --output './backup'
python3 disk_downloader.py --configure
python3 disk_downloader.py --verify
python3 disk_downloader.py --watch 1800
python3 disk_downloader.py --public-url 'https://disk.yandex.ru/d/ВАША_ССЫЛКА' --output './public-backup'
python3 disk_downloader.py --help
```

На Windows замените `python3` на `py -3`. OAuth вводится скрыто, берётся из `YANDEX_DISK_TOKEN` или системного хранилища. Для публичных ссылок он не нужен; пароль, истечение срока и ограничения скачивания не обходятся.

Настройки — в `download.json` или файле `--config`. Аргументы перекрывают настройки запуска. Относительный `output` в JSON считается от папки настроек, `--output` — от папки терминала:

```json
{
  "disk_path": "/Архив",
  "output": "backup",
  "workers": 3,
  "retries": 3,
  "timeout": 60,
  "verify": false,
  "watch": 0
}
```

`--watch`: `0` — один проход, иначе пауза минимум 60 секунд. Диапазоны `--workers`, `--retries`, `--timeout` совпадают с GUI. Отдельного CLI-флага превью нет. Если настройки GUI и CLI находятся в одной папке, они используют общую запись токена.

Коды CLI: `0` — успех; `1` — ошибка настройки / запуска; `2` — частичный результат или неверный синтаксис аргументов; `130` — остановка. Отчёт: `.disk-downloader/last-run.json`.

## Разработка и проверки

Ключевые части исходного проекта:

| Путь | Назначение |
| --- | --- |
| `disk_downloader_gui.py` | Форма, очередь событий и запуск фоновой работы |
| `yandex_disk/api.py` | Постраничный REST-клиент Диска, ссылки оригиналов и превью |
| `yandex_disk/downloader.py` | Обход, докачка, проверки, атомарная замена и база прогресса |
| `yandex_disk/batch.py` | Настройки очереди, последовательные папки и повторные круги |
| `yandex_disk/credentials.py` | Нативное хранилище токенов macOS / Windows |
| `yandex_disk/ui_theme.py`, `ui_clipboard.py` | Оформление, подсказки и вставка |
| `launch-macos.sh`, `launch_windows.py` | Проверка среды и запуск приложения |
| `bootstrap-python-macos.sh`, `bootstrap-python.ps1` | Подготовка официального Python после согласия пользователя |
| `docs/GUI.md` | Краткое руководство для пользовательских архивов |
| `tests/`, `tools/` | Изолированные проверки и сборка архивов |

Для существующих тестов используйте **Python 3.12**, как в CI. Они работают с подставными токенами, временными папками и HTTP-сервером на `127.0.0.1`. Настоящие установщики и запросы администратора не запускаются:

```sh
python3 -m unittest discover -s tests -v
```

Тестам формы нужен доступ к рабочему столу. На macOS / Linux с графической сессией:

```sh
DISK_DOWNLOADER_GUI_TESTS=1 python3 -m unittest discover -s tests -v
```

В PowerShell на Windows:

```powershell
$env:DISK_DOWNLOADER_GUI_TESTS = '1'
py -3 -m unittest discover -s tests -v
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\test_bootstrap_windows.ps1
```

`DISK_DOWNLOADER_KEYCHAIN_TESTS=1` включает нативный тест macOS с отдельной временной Связкой ключей и тестовым токеном; по умолчанию он пропускается.

[GitHub Actions](.github/workflows/tests.yml): Python 3.12, Windows / macOS / Linux. На Windows включены тесты формы и PowerShell 5.1; на Mac — проверки zsh-лаунчеров и загрузчика. Проверки установки используют подставные функции и не подтверждают выполнение настоящего установщика.

## Сборка пользовательских архивов

Из папки исходного проекта:

```sh
python3 tools/build_windows_zip.py --platform windows
python3 tools/build_windows_zip.py --platform macos
```

Результаты: `dist/DiskDownloader-Windows.zip` и `dist/DiskDownloader-macOS.zip`. Другой путь задаётся `--output /путь/к/архиву.zip`.

Упаковщик использует явные списки: общий GUI, модули и иконки, три помощника платформы и [docs/GUI.md](docs/GUI.md) как `README.md`. Исходный README, CLI, тесты, инструменты, другая платформа, настройки, данные, `.venv` и кэши исключены. Unix-права: `.command` / `.sh` — `0755`, остальное — `0644`.

Протокол: [REST API Яндекс Диска](https://yandex.ru/dev/disk/rest/). При изменениях методов и разрешений сверяйтесь с официальной документацией.
